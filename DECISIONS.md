# Decisions

When a detail is not specified, decisions follow this priority: ① meets the prize requirements → ② runs reliably in the demo → ③ simplest implementation.

| # | Decision | Reason |
|---|---|---|
| 1 | The repo root is the `plainpath/` layout itself, so `E:\calhack13` maps to `github.com/kaixiangw564-max/calhack13` | The GitHub repo is already named `calhack13`; an extra nesting level would only complicate paths |
| 2 | The first target site is `https://www.dmv.ca.gov/portal/` (instead of the county site) | The disabled parking placard (REG 195) is handled by CA DMV, which gives the demo questions authoritative answers |
| 3 | `MAX_PAGES=300` by default, configurable in `.env` | Apify credits are uncertain; 300 pages covers the key DMV services with headroom over the ≥50-page acceptance bar |
| 4 | The local machine only has Python 3.14, so use `uv venv --python 3.11` for a 3.11 virtualenv | The stack requires 3.11; uagents and its dependencies are more stable on 3.11 |
| 5 | Agent seeds are stored in `.env` (`*_SEED`) | Agent addresses come from their seeds; fixed seeds keep the Agentverse registration and ASI:One discovery addresses stable |
| 6 | Bitdeer calls use the official `openai` client with `base_url=https://api-inference.bitdeer.ai/v1` | The official docs (developers.bitdeer.ai/docs/api) state the API is OpenAI-compatible; no custom HTTP code needed. Changing the model only requires editing `.env` |
| 7 | Chat model is `deepseek-ai/DeepSeek-V4.1-Flash`; embeddings use Bitdeer's `BAAI/bge-m3` (1024-dim) | Picked from what `GET /v1/models` actually returns; bge-m3 is multilingual, so Chinese questions match English DMV pages directly, and embeddings also count toward Model Studio usage |
| 8 | `config.py` loads the repo-root `.env` centrally | The backend, agents and tests share one config, and nothing depends on the current working directory |
| 9 | Website Content Crawler uses `crawlerType: cheerio` (plain HTTP) | dmv.ca.gov is server-rendered WordPress (checked with curl: the static HTML already contains the full text). Cheapest and fastest: 300 pages cost $0.097 |
| 10 | *(Revised in step 4)* Respect robots.txt per URL. dmv.ca.gov only disallows `/portal/wp-content/uploads/` (and wp-admin). Form links on its pages use `/portal/file/<form>-pdf/`, which returns the PDF directly (`200 application/pdf`) and **is allowed**, so the custom Actor downloads those PDFs and extracts field labels. Any PDF URL under a disallowed path is recorded by name, number and link only (`pdf_status: disallowed_by_robots_txt`) | Hard constraint from section 3. The original step 3 conclusion ("PDFs can't be downloaded") was based only on the robots rule; checking the actual link format showed most forms are reachable legally |
| 11 | Each crawl run is bounded by `maxCrawlPages`, `memory_mbytes=2048` and `run_timeout=30min` | Apify free plan is $5/month; caps the cost of a single run |
| 12 | Tests and ingest read the latest successful WCC run (`last_run(status=SUCCEEDED)`) instead of a hard-coded dataset ID | After re-crawling, nothing needs to be edited |
| 13 | The same page can appear under both `www.dmv.ca.gov` and `dmv.ca.gov`; dedupe by URL path at ingest (step 5) | 1 of the 271 pages is a duplicate; handling it at ingest keeps the crawl input simple |
| 14 | The custom Actor extracts with rules (no LLM): headings, lists, accordions and links become steps, documents, forms, addresses and fees. Plain-language rewriting happens later in the backend with Bitdeer | The Actor needs no secrets, so anyone can run it from the Store; output is deterministic and covered by offline tests against saved HTML fixtures |
| 15 | Each page yields one page-level record plus one record per "how to" section (headings like Apply / Renew / Replace / How do I) | Matches the "one record per service" format in section 6 while keeping page-level context. Navigation-only pages produce nothing |
| 16 | PDF robots checks use Crawlee's `RobotsTxtFile` (protego), not Python's `urllib.robotparser` | dmv.ca.gov's robots.txt has three `User-agent: *` groups. `urllib.robotparser` only keeps the first group and would wrongly allow `wp-content/uploads`; protego merges them (covered by a unit test) |
| 17 | Searchable forms design: in step 5, each unique form becomes its own chunk (number + name + official PDF URL + source page + field labels), and form numbers also get exact-match lookup | Embeddings handle codes like "REG 195" poorly; exact matching guarantees that asking about a form number finds the official PDF link |
| 18 | The Actor's Dockerfile uses `apify/actor-python:3.11`; the Actor has its own `actor/.venv` | Same version as the backend; the Actor's dependencies (apify, crawlee) stay separate from the backend's |
| 20 | Output schema (`.actor/output_schema.json`) exposes one output, `results` = `{{links.apiDefaultDatasetUrl}}/items`; per-field structure lives in `dataset_schema.json` `fields` (JSON Schema draft-07) | The Output schema format only declares output links (title/description/template), so field definitions belong in the dataset schema. Apify validates every pushed item against `fields` and rejects failures, so the schema only requires always-present keys, allows `number: null`, keeps `additionalProperties: true`, and was validated against all 257 real items plus fixture output (no `pdf_status`) before pushing |
| 21 | One Atlas Vector Search index `chunks_vector` (1024-dim cosine on `chunks.embedding`, filters `site` and `kind`) holds both page chunks and form chunks | Free clusters allow at most 3 search indexes; one index plus a `kind` filter covers "any content" and "forms only" queries |
| 22 | Page chunks: split WCC Markdown by headings, merge sections under 120 chars, split above 1500 chars on paragraph boundaries; prefix each chunk with page title + section heading; strip Markdown link URLs | Self-describing chunks retrieve better; URLs add embedding noise, and source links come from the chunk's `url` field. 270 pages became 1,245 chunks |
| 23 | Strip a site-wide title suffix (e.g. " - California DMV") when more than half of the pages share it | Generic (no per-site hard-coding) and keeps titles short for answer citations |
| 24 | Ingest is idempotent: deterministic chunk ids (sha1 of url + kind + index) and, after each ingest, deletion of the same site/kind's chunks from older ingests | Apify can deliver webhooks more than once, and re-crawls must replace stale content |
| 25 | `POST /webhook/apify` authenticates with a shared-secret header (`X-PlainPath-Webhook-Secret`, sent via the ad-hoc webhook's `headers_template`), replies immediately and ingests in a FastAPI background task | Apify times out webhooks after 2 minutes and retries non-2xx; the endpoint is public, so unauthenticated calls are rejected. Webhooks are only attached when `BACKEND_PUBLIC_URL` is public; locally `scripts/run_ingest.py` runs the same ingest code |
| 26 | Hybrid retrieval: form numbers in the question (limited to prefixes that exist in `forms`, e.g. REG/DL) are matched exactly first, then vector search fills the rest | Guarantees "REG 195" returns that form's official PDF link; the prefix whitelist avoids false hits like "CA 94269" |
| 27 | Two-layer not-found: (1) top retrieval score below `MIN_SCORE = 0.83` returns not_found without calling the LLM; (2) otherwise the model may still return `not_found`, and steps without a valid cited excerpt are dropped (none left means not_found) | Calibrated on dmv.ca.gov: related questions score at least 0.857, unrelated ones (fishing license, passport, taxes, pizza) at most 0.807. The gate stops the model answering from memory, and the citation check enforces "answers only from crawled content" |
| 28 | The model cites excerpt numbers (`[2]`); code maps them to `source_url`/`crawled_at` and strips the markers. Form links are resolved from the `forms` collection, never taken from model output | Guarantees every step carries a real crawled URL and timestamp, and URLs can't be hallucinated |
| 29 | Non-English questions are also rewritten into an English search query by Bitdeer; results from both searches are merged by best score | bge-m3 is cross-lingual, but rewriting fixed weak cases (e.g. the Chinese change-of-address question's top hit was teen-drivers) |
| 30 | `reasoning_effort="none"` for all Bitdeer chat calls (overridable via `BITDEER_REASONING_EFFORT`) | DeepSeek-V4.1-Flash is a reasoning model; with thinking on, 1,500 tokens went entirely to reasoning and the answer was empty (`finish_reason=length`). Tested variants: `reasoning_effort=none` gives 0 reasoning tokens. Grounded rewriting doesn't need thinking, and latency dropped to about 10 s per answer |
| 31 | The not-found message and disclaimer are written in English and translated by Bitdeer into the user's language; the response includes the site's crawled contact page | Answers must be in the user's language and point to the official contact when nothing is found; falls back to English if translation fails |
| 32 | The web app calls only its own `/api/ask` Route Handler, which forwards to FastAPI using server-only `BACKEND_URL` | No CORS setup, the backend URL isn't baked into the client bundle (`NEXT_PUBLIC_` vars are inlined at build time per the Next 16 docs), and the backend can move without rebuilding the site |
| 33 | Accessibility baseline: Atkinson Hyperlegible font, 20px base size, high-contrast palette (contrast ratios documented in `globals.css`), 4px focus ring, skip link, labeled controls, `aria-live` status, focus moves to the results heading, `lang`/`dir` on answers, `aria-pressed` on toggle buttons | Targets blind/low-vision and older users; verified with axe-core (WCAG 2.0/2.1/2.2 A+AA + best practices): 0 violations on the empty page and on a results page |
| 34 | Language picker shows native names via `Intl.DisplayNames` at runtime, defaults to the browser language, and drives the answer language plus speech recognition/synthesis voices | Lets people find their own language while keeping the source ASCII-only |
| 35 | Browser capabilities (speech support, browser language) are read with `useSyncExternalStore` (server snapshot: unsupported/"en") instead of setState in an effect | Required by the React 19 lint rule `react-hooks/set-state-in-effect`; avoids hydration mismatches |
| 36 | `llm.chat_json` always uses JSON mode (`response_format: json_object`); `/ask` returns 503 with a readable message if the model output is still unusable, and the web proxy keeps the backend status when the body isn't JSON | A Chinese answer once produced invalid JSON twice (unescaped quotes), causing a 500 that the proxy mislabeled as "service not reachable". With JSON mode: 5/5 repeated runs succeeded |
| 37 | Agents run as uAgents mailbox agents in one Bureau process (`agents/run_all.py`), importing `backend/app/core` directly | One process to deploy; inter-agent messages inside a Bureau are dispatched in-process (verified in `uagents/context.py`: `dispatch_local_message`), so Navigator-to-Answer adds no network hop; no logic is duplicated |
| 38 | Agentverse registration is automated at startup with `AGENTVERSE_API_KEY` by calling uagents' own `register_in_agentverse` (the same challenge/proof/register flow the Agent Inspector's Connect button triggers), including README, description and `starter_prompts` | No manual inspector clicks per agent and per restart; profiles stay in sync with the repo. Requires a key with `av` (read-write) scope; an `av:ro` key fails with "Could not validate credentials" |
| 39 | Navigator calls Answer over a typed protocol (`AnswerRequest`/`AnswerResponse`, `send_and_receive`, 120 s timeout); on failure or timeout it recovers by running the same core pipeline in-process | Real multi-agent orchestration with tool-failure recovery; the user still gets an answer |
| 40 | Intent extraction (Bitdeer, JSON mode, temperature 0) returns {language, service, location, site, question}; a stated language ("I only speak Chinese") wins over the message language; greetings and questions about PlainPath return `question = null` (self-introduction instead of a search) | Matches the spec's Navigator contract; temperature 0 plus explicit renew examples stopped "renew" drifting to "apply" |
| 41 | The Navigator's first chat reply is the full answer (no separate "searching..." message) | Observed: ASI:One's planner called the agent 3 times and ignored it when the first reply was only a progress note. Progress messages are reserved for long operations (live crawls) |
| 42 | Startup warm-up (Atlas ping, known sites, chat labels for 8 languages) runs in a background task; questions already in English skip the query rewrite | Cut one answer from 12.3 s to 5-6 s (2 model calls instead of 4) |
| 43 | Interactive Cards: missing info -> `form` card; steps -> `carousel` (one item per step with official-page CTA and crawl date); documents + forms -> `detail` card as the checklist (summary rows + "Explain <form>" CTAs). Every card message also carries the full answer as Markdown text | Card schemas from the official ASI Interactive Cards doc; clients or planner paths that don't render cards still get the complete cited answer. Card clicks are parsed as JSON first, then treated as prose |
| 44 | Crawler freshness: data younger than `CRAWL_MAX_AGE_HOURS` (24) is used as is; otherwise the full Apify pipeline (WCC -> ingest -> Gov Extractor -> ingest) starts, progress is relayed into the chat for up to `CRAWL_PROGRESS_WAIT_S` (45 s), then the answer uses cached data (with its date) while the refresh finishes in the background. One refresh per site at a time (`sites.status = refreshing`) | A full crawl takes minutes, longer than a chat turn; users get an answer quickly and still see the live refresh. Avoids duplicate paid crawls |
| 45 | Failure recovery: Apify start failure -> cached data with an explicit "could not refresh, data from <date>" note; Crawler Agent timeout -> Navigator checks freshness itself; Answer/Form Agent failure -> same core pipeline in-process. `CRAWLER_SIMULATE_FAILURE=1` injects an Apify failure for the demo | Required "tool failure recovery" with a reproducible, cost-free demo switch |
| 46 | Form checklist candidates = services on the cited pages + services on the top-8 vector-matched pages + forms vector-matched within 0.03 of the best score (floor 0.78) + the pages that link those numbered forms; Bitdeer keeps only items for the user's specific action and prefers guides in the answer language (max 2 unnumbered PDFs) | The crawler and the extractor can store the same page under different URLs (dpp-renewal vs dppp-renewal) and a fixed 0.82 threshold missed REG 195A once the location was added. Verified: renew -> REG 195A, apply -> REG 195, replace -> REG 156, REAL ID (zh) -> the Chinese guide |
| 47 | The Navigator reuses the previous conversation's site only for follow-ups without a service of their own | A new request no crawled site handles (e.g. a fishing license) must get "not covered" plus the form card, not an answer from the last site |
| 48 | Crawl progress uses a request_id plus Future (CrawlRequest, then CrawlProgress* and CrawlResult) instead of send_and_receive | send_and_receive waits for a single reply; progress needs several messages relayed to the user mid-call |
| 19 | Before `apify push`, replay the CLI's file selection (glob + `git ls-files --ignored` + `.actorignore`) to check the upload list | The repo is public and so is the Actor source; make sure `.env`, `storage/` and `.venv/` are never uploaded |
